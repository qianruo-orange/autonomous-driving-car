# 播放器帧率与延迟优化

验证时间：2026-11-02，Asia/Shanghai。使用设备本机 Chromium 156 的无界面模式访问实际 HTTP 视频流，分别载入修改前后的播放器脚本；后端、模型、分辨率和编码质量保持相同。测量时生产服务保持运行。

## 改动

- MSE 接收与 SourceBuffer 写入分离。写入仍串行，写入期间收到的块按原顺序合并，减少小块处理和下载等待；不丢弃 H.264 依赖数据。待写队列上限为 8 MiB，超过上限重连，避免客户端内存持续增长。
- 播放器独立刷新配置和恢复连接，配置请求有超时；系统状态请求挂起不会阻塞视频启动或重连。
- 页面隐藏或离开时释放视频连接，恢复可见时接入实时流，避免后台积累历史缓冲。
- MJPEG 使用可复用缓冲逐字节扫描，避免每个网络块都复制、重扫整张未完成图片；保留解码忙时只补显最新帧的行为，以及 16 MiB 帧上限。
- 自然开始播放的会话也进入自适应缓冲状态。呈现回调停顿超过 250 ms 时，用播放时钟估算延迟，避免旧回调让延迟读数持续增长。

## 本机采样

每组在视频正常播放并预热后采样约 30 秒；帧率采用浏览器视频质量计数，缓冲为 SourceBuffer 末端到播放位置的时间差。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 平均播放帧率 | 28.06 FPS | 29.11 FPS |
| 前端缓冲平均值 | 76.8 ms | 73.5 ms |
| 前端缓冲 P95 | 99.1 ms | 99.6 ms |
| 采样窗口内 waiting / seeking | 0 / 0 | 0 / 0 |
| 未捕获脚本错误 | 0 | 0 |

这些是单次本机采样，源帧率、温度和调度存在波动，不能视为固定增幅。前端缓冲不包含相机采集、推理、编码及网络耗时；不把页面的估算延迟当作外部计时测得的端到端延迟。无界面环境的呈现回调会停顿，因此对比使用浏览器视频质量计数。

## 验证范围

实际源码的 39 项隔离检查通过，覆盖字节顺序、合并写入、单个写操作、队列溢出、EOF 排空、取消旧会话、隐藏与恢复、状态接口挂起、大 JPEG 分片与帧上限，以及过期呈现时钟的回退。测试代码放在工程外，未新增项目测试目录。

浏览器另验证 H.264/MSE 播放、MJPEG 兼容播放，以及模拟 visibilitychange 后连接释放和恢复；原始结果与临时工具位于设备的 `/home/qianruo/kbuild/car-player-browser/`。未对远程手机或实际弱网环境作性能保证。

SourceBuffer 的更新仍遵守 [appendBuffer 的串行更新要求](https://developer.mozilla.org/en-US/docs/Web/API/SourceBuffer/appendBuffer)；呈现时钟参考 [requestVideoFrameCallback 元数据](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)。
