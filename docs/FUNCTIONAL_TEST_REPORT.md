## 发现及修复

1. **模型和标签上传返回 `bad type`。** 查询参数入口错误地包含 `?`。改为从 `q + 1` 解析；实际标签和原模型上传均返回 `result: ok`，同时验证错误 magic、过长标签与未知类型被拒绝。
2. **计划内热重载引起录像线程误停机。** 初轮浏览器上传标签时，录像线程记录 `YOLO inference stalled >1s`，服务退出并被 systemd 拉起。增加明确的重载状态，录像线程在计划内暂停期间刷新等待时间；重载结束后继续保留原有 1 秒推理故障保护。
3. **重载与生产者同时操作队列及游标。** 关闭旧池并唤醒等待者后，等待主生产者完成当前解码/投递与 claim 归还，再清理队列、重置游标并释放模型。新池准备完成后恢复启用。对应代码审查条目 14。

修复版从 23:59:42 起运行，连续标签、模型和阈值重载期间 PID 保持不变，`NRestarts=0`。四次重载后的 3 秒采样中，采集序号增加 67，显示序号增加 66，录像状态保持录制且已产生 2,273 帧。

## 隔离清理与电源验证

在新建的 `/tmp` 目录中直接编译并调用项目实现；文件与录像状态均为独立夹具。验证单文件删除、录像批量清理、日志清理、日报及其边车文件清理、路径穿越拒绝、全页面删除计数，以及活动/收尾中的录像、无关文件和符号链接目标保留。完成后删除夹具。

重启与关机处理函数实际执行到响应和同步/电源调用边界，链接层拦截 `sync`、`reboot`，确认分别请求 `RB_AUTOBOOT`、`RB_POWER_OFF`。设备未因测试重启或关机。现场批量删除仅验证取消确认，实际批量删除使用上述隔离夹具。

临时脚本有两处断言需要纠正：保存接口返回文本 `saved`，空上传可能在内容处理器前返回空响应体。浏览器 DevTools 两次无法读取已经逐出缓存的上传响应，补测改在页面内读取实际 fetch 响应，并核对界面热生效提示。原始失败记录保留在临时结果目录，未将这些脚本问题计为产品通过结果。

## 未覆盖与限制

- 当前没有配置 CAN 接口和电机。实际总线收发、CAN FD、DBC 上传后的在线信号解码、电机驱动与闭环跟随未验证；没有启用跟随驱动车辆。
- 采样时未检测到可选目标，因此真实目标选择、外观重识别与丢失后恢复未验证。
- 当前设备未提供可用硬件编解码器，已验证能力返回及软件链路；硬件编码/解码路径未验证。
- 静态 IP、DHCP 和接口切换会影响当前连接，本轮只读取配置和保存原 ANO 设置，未改变实际网络地址。
- 上述凌晨测试时尚未切换 RT 内核，FIFO/实时调度未验收；当时内核 `-j24` 构建并行运行，浏览器实测为 3–5 FPS。2026-11-02 上午已完成 RT 内核及全线程实时调度补测，见 [内核与调度验证报告](KERNEL_VERIFICATION.md)。
- 仍未注入磁盘满、长期 I/O 故障、大量录像列表、驱动缓冲异常、设备热拔插等故障；`CODE_REVIEW.md` 中其余问题继续保留。
- 临时 Chromium 环境缺少中文字形，截图中的中文显示为方框；文案与交互检查基于 DOM，本轮未进行视觉像素验收。
